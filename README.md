# DroBinG Backup

Переносимая программа Windows x64 для резервного копирования выбранных файлов VDS по SSH на флешку, внешний или внутренний диск.

[Описание и инструкция](https://drobing.ru/backup/) · [Скачать готовую программу](https://github.com/DroBinG/DroBinG-Backup/releases/latest)

## Возможности

- Сохранённое расписание: по умолчанию каждые 24 часа после успешной копии. Проверка срока через Планировщик Windows каждые 15 минут.
- Поиск носителя по аппаратному номеру, номеру тома и контрольному файлу; смена буквы диска не сбрасывает привязку.
- Проверка закреплённого SSH-ключа до авторизации. Пароль хранится в Windows Credential Manager текущего пользователя.
- SQLite online backup с quick_check. Результат: tar.gz, SHA256 и описание снимка.
- Настраиваемое число копий, отмена передачи и встроенный офлайн-справочник по F1.

## Начало работы

1. Скачайте ZIP из Releases, распакуйте и откройте `DroBinGBackup.exe`.
2. Выберите носитель, укажите **свой** сервер, SSH-порт, логин и пароль.
3. Получите SSH-ключ и сверьте отпечаток с доверенным источником.
4. Укажите абсолютные пути Linux (по одному на строку), интервал и лимит копий.
5. Сохраните настройки и запустите первую копию. Подробности: кнопка «? Справка» или [HELP.txt](HELP.txt).

В публичном пакете нет настроек, паролей и резервных копий сервера разработчика. Новая установка открывается с пустыми адресом, логином и ключом. Python на Windows не нужен; на VDS должен быть python3.

## Сборка

Требуются Visual Studio 2022 C++ Build Tools (x64), Windows SDK и PowerShell. Запустите:

```powershell
.\build.ps1
```

Скрипт проверяет SHA256 приложенного исходного архива libssh2 1.11.1, собирает статическую библиотеку WinCNG и `DroBinGBackup.exe`. Загрузка зависимостей из сети не требуется. C++17, Win32, статический CRT; на ПК пользователя не требуется установка Python.

## Ограничения

Для расписания нужны включённый ПК без сна, вход в Windows, интернет и подключённый носитель. Окно можно закрыть. На другом ПК учётные данные и расписание настраиваются отдельно.

Передача защищена SSH, но архив на носителе **не зашифрован**. Копируются выбранные пути, а не вся ОС. Нет общей атомарности разных файлов и баз работающего сайта. Для MySQL/PostgreSQL нужны штатные дампы. Автоматического восстановления на VDS нет; заранее проверяйте порядок восстановления.
